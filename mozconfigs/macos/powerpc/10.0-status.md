# Mac OS X 10.0 deployment work

The required PowerPC target is Mac OS X 10.0 through the later PowerPC releases.
All four applications build and package on Linux against original 10.0
libraries and pass their packaged original-OS GUI checks. The full local `act`
build/runtime/upload matrix passes for all four applications. The 10.3.9
profiles are intermediate targets, not the required minimum. GitHub-hosted
runs and physical PowerPC hardware have not been tested.

## Reproducible Linux build

The four `cocoa_*_10.0_gcc.mozconfig` profiles use the existing configure/make
build system. The workflow is
[macos-powerpc.yml](../../../.github/workflows/macos-powerpc.yml), driven by
`build/macosx/build-10.0-ci.sh APPLICATION NEW_WORK_DIRECTORY`. It builds a
Linux/386 Apple GCC toolchain environment, prepares pinned inputs, compiles the
application, audits the package, and prepares original-OS runtime tests.
QEMU runs in a separate container native to the Linux host; do not put it
inside the emulated Linux/386 compiler container on arm64 hosts.

`prepare-10.0-sdk.py ORIGINAL_CD PREPARED_10.1.5_SDK NEW_OUTPUT` uses `7z` and
`bsdtar` to combine checksum-pinned **10.1.5 headers** with original **4K78
libraries**. This is an adapted SDK, not an original 10.0 developer SDK.
Its provenance manifest records the source and hashes. The output has 124
distinct Mach-O files, including the original private CFNetwork and
SystemConfiguration locations and QuickTime/AGL from Essentials.

The original CD SHA-256 is
`e6fbc5c9ae633637777b5f2a9b9be3d8e3779cde02e2c7a2bec5dcc453951dc3`;
its SHA-1 is `23d00b0d6ec621a997b423d89dedd52db1da119b`.
Keep SDKs and work directories separate from developer builds and shared SDKs.
After saving artifacts and logs, remove only completed, owned matrix workspaces
before starting the next local matrix job.

The SDK adaptation preserves original ABI conventions while making headers
usable with GCC 4: dyld retains its integer enum return type, obsolete
Objective-C linkage spelling becomes C linkage, Foundation C functions receive
C linkage in Objective-C++, and the Kerberos packing pragma becomes a balanced
four-byte push/pop. Darwin's 32-bit `rune_t` is independent of Mozilla's
16-bit `wchar_t`. Without that correction, `-fshort-wchar` makes inline ctype
functions misread the OS locale tables and command-line option comparison
fails, despite intact arguments. The target ctype probe reproduces the old
ASCII mapping failure and verifies the corrected ABI.
The declaration in `stdlib.h` must be corrected as well as `runetype.h`:
Toolkit includes stdlib first and otherwise still receives 16-bit `rune_t`.
The target probe now compiles and runs both header orders. A startup trace
confirmed intact arguments with incorrect lowercase mapping before the fix.

Toolkit relaunch now resolves the requested `argv[0]` before falling back to
the Cocoa bundle executable. Original 10.0 can report a different executable
for a directly invoked program beside an application. A regression reproduces
that selection and passes with the correction; packaged tests also exercise
absolute and PATH-based invocation. Those three forms pass in the corrected
Browser, Calendar and XULRunner packages. Full application startup also
requires correcting the original loader's lazy binding mode.
The clean Browser passes GUI/navigation with `DYLD_BIND_AT_LAUNCH=1`, without
an injected tracer. It also passes with only `MH_BINDATLOAD` set on the
executable and no environment override. `config/config.mk` therefore adds
`-bind_at_load` to target-10.0 Toolkit program links; packaging requires the
main executable's flag. All three rebuilt Toolkit applications pass their full
GUI tests with ordinary launches. Calendar uses a test-only command-line
component because its historical handler ignores `-chrome`; the real Calendar
window and event component pass without changing that application.

## Linker, startup and C++ runtime

`build-early-ppc-linker.sh` rebuilds the pinned classic
`odcctools-20090808.tar.bz2` linker with the narrow 10.0 target-parser and Linux
host fixes. It stays separate from the Panther toolchain. These old Mach-O
binaries do not encode minimum-OS metadata, so accepting a deployment flag
alone does not establish compatibility. The GCC driver has a hard-coded linker
path; the wrappers compile objects and invoke the required classic linker.

The original startup source is Apple's
[Csu revision 8097534](https://github.com/apple-oss-distributions/Csu/tree/809753418c8044b256903fa84f03e69f1b5531a7),
selected by the `distribution-macOS` tag `mac-os-x-100`.
`prepare-ppc-startup.sh` installs `crt1.o`, `dylib1.o` and `bundle1.o` under
`/opt/mac/lib/zoolrunner-cheetah` for the explicit 10.0 target. The startup
integration includes GCC frame registration after original key-manager
initialization; otherwise exception unwinding aborts despite a successful link.

`csu-10.0-optional-hooks.patch` resolves optional Objective-C/Carbon hooks with
original dyld APIs instead of exporting common placeholders. The original
placeholder collides with the real Objective-C runtime when a component loads
Cocoa after startup, particularly with eager binding. The graphical guest's
`early-late-cocoa` probe passes delayed loading and NSObject construction under
`DYLD_BIND_AT_LAUNCH=1` with this correction.

The private C++ runtime is built by `build-early-stdlib.sh`. Its original-OS
probes pass allocation, RTTI, exception/destructor unwinding, throwing-static
retry, eight-thread initialization, strings, vectors, streams and exceptions
across libraries. A separate executable/two-library probe passes shared-template
coalescing (`same=1 value=42`). These results cover the tested cases, not every
C++ ABI interaction. See [early-cxx-runtime.md](early-cxx-runtime.md).
Wide-character C++ streams are omitted; application Unicode support remains.

## Platform integration and target probes

NSPR uses original library-hinted dyld interfaces and Mach thread suspension
where `pthread_kill` is unavailable. Tests cover named semaphores, numeric IPv4,
GC-thread register capture/resumption and native plugin loading. A failed
native Mach-O load must not fall through to the CFM loader; the negative missing
plugin-dependency test is followed by a successful valid plugin load.

SQLite 3.53.4 and NSS's separate SQLite 3.7.15 pass recursive entry, 800
concurrent inserts, aggregates and integrity checks for memory and file-backed
databases on 4K78. Their versions are unchanged by this portability work.
Host ThreadSanitizer checks also pass for the early mutex adapter.

The early Quartz bridge uses Cairo's existing software renderer. Host and
original-OS comparisons cover orientation, native damage holes, transparency,
clear operations, radial gradients and transformed dashed strokes. Native and
Panther paths retain their 500-stroke tests. ATSUI shaping and Cairo glyph
placement pass on 4K78. Outline callbacks retain their own allocation-error
status because the original API's callback-result output is unreliable. The
large-point-size outline scaling follows Apple's
[ATSUI Programming Guide, pages 124–127](https://leopard-adc.pepas.com/documentation/Carbon/Conceptual/ATSUI_Concepts/atsui.pdf)
and preserves QuickDraw coordinate direction.
The translated-context test initially reproduced glyph ink seven pixels below
its expected baseline. Cached outlines now omit CTM translation while retaining
font-matrix translation; the corrected original-OS test ends at baseline 40
instead of 47. Suite's text now paints inside its HTML layout box. The image
optimization probe additionally checks RGB/alpha readback: native ARGB word
shifts must not be reversed on big-endian CPUs. The original-OS test reproduces
a red channel of 0 instead of 255 before the correction and passes afterward.
The separate image-frame row test reproduces another defect on native arm64:
the historical Mac bottom-up macro must exclude Cairo's top-down buffers.
Both row and channel checks pass after the native rebuild and on original
10.0 PowerPC. The latter also passes Suite navigation; screenshot comparison
confirms corrected toolbar sprite orientation and text placement.

NSS initialization, known-answer checks, authenticated-decryption rejection,
shutdown/reinitialization and SQL database creation pass using original
AppleCSP. The disposable guest includes that provider from the same CD's
Essentials package. Cocoa tests pass custom classes, inheritance, protocols,
a dynamically loaded Objective-C bundle and a window/event loop.

MailNews RDF utility constructors and service state remain local to each
component under original flat-namespace loading. Pre-Jaguar builds omit the
unavailable system AddressBook framework while retaining local and LDAP address
books. Existing application-facing APIs are preserved by the early deployment
paths; the original SDK/library audit is separate from runtime acceptance.

The regexp matcher now initializes its statics pointer before operations that
can abort, so early cleanup receives a valid pointer. The JSAPI regression
interrupts backtracking through the branch callback and checks recovery in the
same context. It does not depend on reproducing undefined behavior as a crash.

## Original-OS runtime harness

`wrap-10.0-cd.py` adds a 32 KiB Apple partition map around the unchanged original
HFS-wrapper payload so OpenBIOS can boot it. QEMU 11.1.1 boots the original
console and desktop. Debian QEMU 7.2 passed console probes but failed desktop
startup; the runtime Dockerfile builds checksum-pinned 11.1.1 natively.

`run-10.0-guest.py` uses QEMU and hfsutils alone. It creates disposable transfer,
scratch and home volumes, formats HFS+ with the guest's own tool, runs the
payload, then retrieves logs and the result after shutdown. No macOS host
mount utility is required. Screenshots and logs survive failures. Success
requires the payload completion flag: original zsh's EXIT trap can otherwise
misreport an explicit early exit as successful.

The boot CD lacks some installed-system files. `prepare-10.0-system-files.py`
extracts original AppleCSP, QuickTime and AGL from Essentials into an owned
copy. It removes only that copy's already-extracted installer archive to make
space and preserves existing runtime files. The original input stays read-only.
The guest mounts `/.vol` before Carbon filesystem tests and recognizes canonical
`/private/tmp` mount paths. The graphical harness provides a writable filesystem
at the original root-user home path for profile APIs.

Original tar corrupts an exactly full 100-byte name field by appending the
following mode field. This affected real component/plugin paths.
`build/macosx/legacy_tar.py` splits affected paths into the USTAR prefix to
retain a terminating NUL. Host and original-OS tests cover 99/100/101-byte
paths. All early application, test and system-file archives use that writer.

The packaged GUI test creates a disposable profile, checks its actual directory,
exercises XUL textbox layout/selection and preferences, then opens application
chrome. Suite/Browser navigate a local HTML/CSS page; Calendar creates an event;
XULRunner's Simple application calls both JavaScript and C++ XPCOM components.
Suite appends the profile name to the supplied directory. Historical successful
profile creation can exit with status 1, but acceptance still requires the
subsequent GUI checks and an explicit result. Simple uses the default-chrome
preference because its command-line handler does not implement `-chrome`.
The test driver is registered as a chrome package through both the Suite's RDF
registry and Toolkit manifests. A plain file URL does not grant it access to
privileged application interfaces. The harness waits for the final GUI result
when Toolkit asynchronously relaunches during first-run setup.
